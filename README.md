# AusFlow iOS

Driver app for recording grease trap pickups. Expo SDK 58 (React Native), talks to the **UAT** AusFlow API (`src/lib/config.ts`).

Features: sign in with an AusFlow web console account, choose transport company / driver / vehicle, scan a device QR code (or enter it manually), start a pickup with GPS, finish it with the volume collected, browse devices (overdue, nearby) and pickup history.

## Develop

```bash
npm install
npx expo start          # needs a development build on device; Expo Go lacks some native modules
npm run typecheck
npm run lint
npm test                # unit tests (jest-expo), src/**/__tests__/*.test.ts
```

`ios/` is generated by `npx expo prebuild` and is not committed. Configure native settings in `app.json`.

Feature inventory: [docs/features.md](docs/features.md). Old WasteID feature port: [docs/old-features-port-plan.md](docs/old-features-port-plan.md). Tester checklist: [docs/tester-checklist.md](docs/tester-checklist.md) (shareable page: [docs/tester-guide.html](docs/tester-guide.html)).

## Tests

Only unit tests run locally. Building and functional testing are two separate GitHub Actions workflows:

- **Build** (`.github/workflows/build.yml`) runs when the app's own files change (`src/`, `assets/`, `app.json`, package files): typecheck, lint, unit tests, then a Release build for the iOS simulator, kept on GitHub for 30 days as an artifact named by `ci/app-artifact-name.sh` (Xcode version + content hash of the app files). If that artifact already exists it does not build again. When it uploads a new build it starts E2E.
- **E2E** (`.github/workflows/e2e.yml`) never compiles. It runs when `.maestro/` changes, when Build starts it, or by hand: it downloads the build of the current app files and runs the [Maestro](https://maestro.mobile.dev) flows on a simulator. If that build is still being made it stops quietly (Build will start it); if there is none it fails and asks for a Build run. The JUnit report and screenshots are uploaded as `maestro-<run>`.

So changing only flows takes about 10 minutes, and a failing flow never causes a rebuild.

| Flow tag | Needs | What it covers |
| --- | --- | --- |
| `smoke` | nothing | login screen validation and server error |
| `auth` | secrets `E2E_USERNAME`, `E2E_PASSWORD` (an `ops` account on UAT) and variable `E2E_READY=true` | sign in, Today, Me data summary, sign out |
| `data` | also variables `E2E_COMPANY`, `E2E_PLATE`, `E2E_DEVICE` (and `E2E_DRIVER` when the company has several drivers) | join a vehicle by registration; choose driver/vehicle, find a device by code, start a pickup and cancel it |
| `write` | (marker) | the flow writes to UAT; the pickup flow cancels its pickup, which deletes it |
| `admin` | also secrets `E2E_ADMIN_USERNAME`, `E2E_ADMIN_PASSWORD` (an `admin` account on UAT) | the console: dashboard, Devices / Records / Me tabs, device page and QR label, alerts, ops tickets, directory → company → driver, switching between console and driver view |

Flows whose secrets/variables are missing are skipped with a warning.

The E2E accounts (`e2e_ops`, `e2e_ops2`, `e2e_view`, and `e2e_admin` created through the console's user admin) and test data (company `E2E Transport`, vehicles `E2E 001`/`E2E 002`, device `E2E-DEV-001`, facility `E2E Treatment Plant`, all ids `E2E-…`) exist only on UAT, seeded by `migrations/0015_uat_e2e_seed.sql` on the backend's `uat` branch. Their passwords are repository secrets; the workflow defaults the test-data variables to these values.

## Ad Hoc builds (GitHub Actions)

Every push to `main` (or a manual run of **iOS Ad Hoc**) builds a signed IPA on a macOS runner and publishes the install page to GitHub Pages: <https://belimked.github.io/ausflow_ios/>. The IPA is also kept as a workflow artifact for 30 days.

Repository secrets:

| Secret | Content |
| --- | --- |
| `IOS_DIST_P12_BASE64` | Apple Distribution certificate + private key (`.p12`), base64 |
| `IOS_DIST_P12_PASSWORD` | Password of the `.p12` |
| `IOS_ADHOC_PROFILE_BASE64` | Ad Hoc provisioning profile for `com.ausflow` (`.mobileprovision`), base64 |

Team ID `8J42Q87M5P` and bundle ID `com.ausflow` are set in the workflow.

### Adding a test iPhone

Full bilingual guide (UDID → install): [docs/ios-adhoc-manual.md](docs/ios-adhoc-manual.md).

1. developer.apple.com → Devices → register the iPhone's UDID.
2. Profiles → edit the Ad Hoc profile, tick the new device, save and download it.
3. Replace `IOS_ADHOC_PROFILE_BASE64` with `base64 -w0 profile.mobileprovision` and re-run the workflow.

On iOS 16+ testers must enable **Settings → Privacy & Security → Developer Mode** once (the install page explains this).
